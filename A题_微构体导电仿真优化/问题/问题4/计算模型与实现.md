# 问题4计算模型与实现

## 推导到代码的映射

| 数学对象或合同 | 实现位置 | 机器可读证据 |
|---|---|---|
| D 边界 A 中心线切段 | `microstructure_sim.fragment_trial`，配置 `BoundaryMode.D` | trial 诊断中的 `a_fragment_count`、`internal_a_edges=0` |
| 球片 $\operatorname{Ball}(c-kL,r)\cap Q$ | `mixed_microstructure_sim.fragment_sphere`、`ClippedSphere` | `b_fragment_count`、`clipped_b_fragment_count` |
| 截球 support 与 GJK | `ClippedSphere.support`、`evaluate_exact_contact` | 窄相调用及收敛诊断 |
| 最大静态图的二维 minimax 前沿 | `solve_pareto_connectivity`、`pareto_minimax_result` | 每个 trial 的 `connectivity_frontier`、`pareto_search` |
| 精确成本权重与更便宜极大集 | `cost_weight`、`cheaper_maximal_frontier` | 冻结文件中的候选、整数域计数和极大前沿 |
| Bonferroni 单侧确认 | `build_confirmation_freeze`、`run_confirmation` | `q4_confirmation_freeze.json`、确认 JSON/CSV |
| 证据不足自动降级 | `analyze_confirmation_records` | `q4_summary.json` 的 `result_status` 和未决成本区间 |

权威脚本为 `问题/问题4/src/solve.py`，D 混合几何与分片/续跑内核位于
`公共代码/mixed_microstructure_sim.py`，二维路径算法位于
`公共代码/pareto_connectivity.py`。

## 参数、单位与随机流

题面纳米尺寸直接进入几何核；名义体积在输出层换算为 $\mathrm{\mu m^3}$，成本按
$W=567N_A+64N_B$ 比较后再乘 $\pi/120000$ 元。随机量采用
`SeedSequence([master_seed, stream_id, trial_id, quantity_code])`：A 中心、A 方向和
B 中心使用不同 quantity code，同一类型的短设计与长设计保持逐元素前缀一致。

正式配置由 `项目配置.json` 冻结：主边界 D，目标概率 0.90，探索流 `stream=4`、
`n=2000`，确认流 `stream=5`、`n=50000`。确认流与探索流不同；同一阶段的所有
设计共享一个最大静态图 artifact。截球球内外判据使用 `math.fma` 的误差项，因此
运行环境要求 Python 3.13 或更高版本；旧版本会明确失败，不静默降低几何认证等级。

## 单个 trial 的计算顺序

1. 按最大 $(N_A,N_B)$ 生成 A/B 随机前缀。
2. A 按 D 中心线语义切段；B 枚举相邻 $3^3$ 个胞，保留正体积球盒交集并映回基础盒。
3. 以 AABB 空间哈希产生候选实体对；A-A 用既有圆柱核，涉及球片的 A-B/B-B 用通用 GJK，完整球对保留闭式加速。
4. 不添加任何同源内部边，也不做 minimum-image 或 ghost；以 support 投影判断左右电极接触。
5. A 源 $i$ 的全部片段赋阈值 $(i,0)$，B 源 $j$ 的全部片段赋阈值 $(0,j)$，计算左右路径的非支配分量 minimax 标签。
6. 任意设计只需查询是否存在标签 $(a,b)\le(N_A,N_B)$，无需重新构图。

探索和确认各自只构建一次最大前缀图。该实现减少重复几何计算，同时与逐设计固定图
在相同随机前缀下严格等价。

## 两阶段统计求解

探索设计可由矩形网格或重复 `--design N_A,N_B` 显式给出。脚本先计算全部探索点的
点估计，并在点估计不低于 0.90 的设计中按 `(W,N_A,N_B)` 选最小候选。探索区间只
用于诊断，不作为最终概率证据。

冻结阶段写入候选、全部严格更便宜极大点、等成本设计、确认最大静态图、独立 stream、
固定 trial 数以及 $g=1+|\mathcal M|$ 的 Bonferroni 分配。若同一路径已有冻结文件，
协议内容发生任何变化都会报错；探索 JSON/CSV 的 SHA-256 也随冻结文件保存。

确认阶段只读取冻结协议。候选以 Clopper--Pearson 单侧下限判定，更便宜极大点以
单侧上限判定；Wilson 仅作诊断。三种结果状态为：

- `globally_certified_minimum_cost`：候选确认可行，且全部严格更便宜极大点被排除；
- `lowest_statistically_feasible_cost`：候选确认可行，但尚有更便宜点未排除；
- `screening_candidate_not_confirmed`：候选未确认，不报告最低成本。

## 分片、续跑与输出

每个 batch 使用确定 trial ID，写入包含完整配置指纹的 JSON 分片。串行和多进程均在
每个 future 完成后立即校验并原子落盘；后续批次失败不会丢失已完成分片。续跑时，
trial 范围或配置指纹不一致会被拒绝。

主要输出为：

- `q4_screening.json`、`q4_screening.csv`：探索点查询结果；
- `q4_confirmation_freeze.json`：不可静默修改的确认协议；
- `q4_confirmation.json`、`q4_confirmation.csv`：确认计数、区间和判据；
- `q4_summary.json`：最终证据等级、设计、成本/体积和未决区间；
- 各阶段 `mixed_pareto_frontier_samples.json` 及 `shards/`：可复核的 trial 前沿。

## 运行命令

正式计算前可先用显式小设计检查环境：

```powershell
python "问题/问题4/src/solve.py" --stage screen --design 0,0 --design 1,0 --screening-trials 2 --workers 1 --no-resume
```

正式流程使用配置默认的 2000/50000 次数，可分阶段执行：

```powershell
python "问题/问题4/src/solve.py" --stage freeze --workers 16
python "问题/问题4/src/solve.py" --stage confirm --workers 16
```

也可用 `--stage all` 连续完成。当前交付只完成求解器与小规模验证，尚未启动正式大样本，
因此结果文件出现前不能填写最优粒子数或成本。
