# 问题3计算模型与实现

## 两阶段固定协议

权威入口为 `问题/问题3/src/solve.py`。问题2正式 D 边界的
`results/threshold_samples.json` 只作为探索流：程序校验配置指纹、完整 trial ID、边界模式和
SHA-256，再由首次导通数的经验分位定位阈值 `t`。默认冻结
`max(0,t-4),...,min(max_count,t+4)`；也可用 `--candidates` 在看到确认数据前显式覆盖。

冻结文件 `q3_confirmation_freeze.json` 在确认仿真开始前写入，包含：

- 问题2探索文件绝对路径、SHA-256、配置和经验阈值；
- 冻结候选整数、目标概率、候选选择方法；
- 确认样本数、D 边界、master seed 和独立 `stream_id`；
- 确认配置指纹及 Bonferroni 错误率分配。

续跑时若输出目录已有冻结文件，程序要求其内容逐字段相同；协议变化必须使用新目录，防止在
看到确认结果后静默更换候选或样本预算。

## 独立共享确认流

确认配置继承探索流的几何尺寸、阈值、空间网格和数值容差，只把 `max_count` 缩至冻结候选的
最大值，把 `trial_count` 固定为 50000，并将默认 `stream_id` 从问题2的 2 改为 3。候选之间
共享同一批首次导通阈值，因此一次前缀仿真可同时计算全部候选；确认流与探索流独立，但不会
把每个候选误当作一套新的 50000 次仿真。

确认流由公共 `run_simulation` 生成，分片保存于 `results/confirmation/shards/`，支持固定 trial
ID 的多进程、断点续跑和配置指纹检查。合并文件为
`results/confirmation/threshold_samples.json`。

## 联合概率判定

设预冻结候选数为 `m`。每个候选同时计算一个单侧下限和一个单侧上限，共 `g=2m` 个预定
陈述。总体错误率为 0.05，故每个界使用

\[
\alpha_i=\frac{0.05}{2m},\qquad 1-\alpha_i
\]

的单侧置信水平。程序同时输出 Wilson 和 Clopper-Pearson 界；Wilson 只作数值诊断，最终
结论以 Bonferroni-Clopper-Pearson 精确界为准：

- 下限不低于 0.90：统计可行；
- 上限低于 0.90：统计不可行；
- 其余：未判定。

只有冻结候选 `N` 的精确下限不低于 0.90，且 `N-1` 也在冻结集内并且精确上限低于 0.90，
才输出 `result_status=confirmed_minimum`。否则输出
`result_status=minimum_not_confirmed`、最低统计可行整数和冻结集内未判定区间，不把点估计首次
越过 90% 写成真实最小值。程序还以最大统计不可行整数加 1 为下端、最小统计可行整数为上端，
构造最小整数的联合置信括界；若括界两端换算后在百分号后两位相同，则只确认题目要求精度
下的填充量，不把它扩张为唯一整数结论。

## 输出与量纲

`q3_summary.json` 保存冻结文件及确认流哈希、两阶段配置指纹、全部候选的成功次数、点估计、
单侧 Wilson/精确界、三分判定和最终证据层级。报告整数的名义体积分数先保留未舍入值，再按
题意显示百分号后两位；显示值不参与整数搜索。

## 复现命令

正式运行默认读取问题2正式结果并执行 50000 次确认：

```powershell
python "问题/问题3/src/solve.py" --workers 8 --batch-size 100
```

若问题2正式文件在其他位置，应显式指定：

```powershell
python "问题/问题3/src/solve.py" `
  --threshold-artifact "问题/问题2/results/threshold_samples.json" `
  --output-dir "问题/问题3/results" `
  --confirmation-trials 50000 --confirmation-stream-id 3 `
  --workers 8 --batch-size 100
```

自动测试只使用显式的 `--confirmation-trials 3` 临时目录，不会触发正式大样本。
